# Shader-to-readback pipeline interface repair

This is an **original deliberate fault injection**, not a recovered production
bug or external-engineering acceptance. The same real GLSL shader writes uint 42
to set 0, binding 0, a storage buffer. Official glslang compiles it for Vulkan 1.1;
SPIRV-Tools validates and disassembles that exact binary before use in all runs.

The runner copies baseline.c, actually applies fix.patch with fuzz disabled, checks
that the patch changed exactly one macro from UNIFORM_BUFFER to STORAGE_BUFFER,
and independently compiles both sources. The patch does not change the shader,
descriptor write, output expectation, dispatch or synchronization.

| Case | Actual behavior | Expected evidence |
| --- | --- | --- |
| baseline bad-type | Shader SSBO versus layout UBO | pipeline-create VUID 07990, callback abort |
| patched good | Compatible SSBO layout, descriptor write, dispatch, barrier, fence, readback | value 42, no validation errors |
| patched missing-binding | Layout moves declaration to binding 1 | pipeline-create VUID 07988, callback abort |
| patched wrong-output | Same valid dispatch reads 42, oracle intentionally expects 43 | exit 6, no validation errors |

Full VUIDs are `VUID-VkComputePipelineCreateInfo-layout-07990` and
`VUID-VkComputePipelineCreateInfo-layout-07988`. Rejected pipeline creation must
return `VK_ERROR_VALIDATION_FAILED_EXT` and exactly one expected diagnostic at
that phase. Invalid pipelines are never dispatched. Cleanup errors are checked;
timeouts, unrelated diagnostics and crashes cannot count as an expected result.
The wrong-output case is only an oracle negative, not a discovered GPU fault.

## Runtime scope

The probe queries API version, CPU device identity, storage-buffer/range and compute
invocation limits, a compute queue family, memory compatibility bits, and a
HOST_VISIBLE | HOST_COHERENT memory type. It enables no optional device features;
this simple compute shader only has `OpCapability Shader`. A compute-to-host
buffer barrier plus fence wait precedes the coherent readback. This does not prove
noncoherent visibility, mobile performance or hardware qualification. Ordinary
Validation is used, not SyncVal or GPU-AV.

```sh
# Configure VK_DRIVER_FILES, VK_LAYER_PATH and loader library search paths first.
python -O cases19/pipeline_interface/run.py --tools "$TOOL_BIN" \
  --include "$VULKAN_INCLUDE" --loader "$VULKAN_LOADER" \
  --output "$FRESH_OUTPUT"
```

The fresh output directory contains the actually patched source, binaries, SPIR-V,
disassembly, every stdout/stderr log and summary.json. Summary binds source,
patch, runner, loader, tool version/binary, manifest, shader and executable hashes,
plus exact mode, identity, memory selection, diagnostics and return codes. Raw
compiler commands use `gcc -Wall -Wextra -Werror`; GLSL uses
`-V --target-env vulkan1.1 -S comp`. No source assets are generated by a substitute
renderer and no pre-existing output is accepted.

## Actual rule/API pairing

The runner invokes `tools/pipeline_interface19.py` on the actual disassembly with
its SHA and paired successful validator record. Each C process prints the layout
fields from the `VkDescriptorSetLayoutCreateInfo` it actually submitted. The rule
compares those records with reflection; the runner requires its exact VUID list to
match the real Validation callback. The missing-binding mode truthfully records
binding **1** (not an invented empty layout), so shader binding 0 is missing.
Both good and wrong-output pass interface admission; only the latter fails the
separate readback oracle. The summary records rule-source SHA, paired reflection,
actual per-process layout and admission without upgrading interface admission to
complete runtime correctness.
