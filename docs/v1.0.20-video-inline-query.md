# v1.0.20 R3: bounded Video inline-query admission

The Skill's existing [Video contract](https://github.com/oahc09/vulkan-rendering-expert-skill/blob/ebdd217eb5a332aa45a0e601ce12d97f17563a3a/references/03_api_manual/04_buffer_image_memory/image.md#vulkan-video-codec-differences)
marks maintenance1 inline-query usage as an open review area. This Tests-only
change supplies a scoped decision model and source index. It does not change the
Skill pair SHA, historical domain ledger, original acceptance or release status.

- Begin from actual supported and enabled extension/feature evidence, and require
  the inline flag on the session being used. Do not mix ordinary begin-query
  commands into an inline-flagged coding scope.
- For one command, check first/count separately from the required operation
  count. Declare the selected slot's availability at ordered command execution;
  do not infer availability from a stale host poll or substitute an unsafe reset.
- Decode accepts status-only. Encode accepts status-only or encode feedback.
  The status query condition follows the command pool's queue family. The pool's
  creation profile must match the complete session profile; a codec name or
  equal pointer labels cannot establish it.
- No inline request is not a runtime pass. An unsupported path can separately
  choose legal non-inline coding or a platform codec, neither of which counts as
  inline query evidence. Invalid caller metadata cannot produce admission.
- Counterexamples change one supplied field at a time and compare against
  explicit VUIDs. They are declaration-level models, not attempts to submit
  invalid Vulkan calls. The cross-direction control also reuses a separately
  admissible encode-feedback model pool and rejects both its type and profile in
  decode.

Run with the usual exact Skill checkout and pytest:

```sh
python -m pytest -q tests/test_video_inline_query20.py
```

No driver execution, physical capability or complete Video/SC domain review is claimed.
