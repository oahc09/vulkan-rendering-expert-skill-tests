# v1.0.19 bilingual diagnostic handoff (bounded C3/C4/C7)

The original plan's delivery requirements (§19, §21.2, §24 C3/C4 and stage reports)
include inputs, actual reads, logs, patches, tests, before/after evidence and unknowns.
This milestone makes the five existing local chains reviewable; it does not add a
new Vulkan probe or claim external-project blind acceptance.

## Build only from strict, paired evidence

Run from the exact committed tests checkout also named by the strict bundle:

```sh
python -O checks19/build_diagnostic_handoff.py build \
  --bundle "$STRICT_BUNDLE" --normative-report "$STRICT_NORMATIVE_REPORT" \
  --tests-root "$TESTS_ROOT" --skill-root "$SKILL_ROOT" \
  --validusage "$PINNED_VALIDUSAGE_JSON" --output "$FRESH_HANDOFF_OUTPUT"
```

All source dependencies are checked against that commit before import. The build
re-verifies raw bundle logs/artifacts, source and Skill pair, process cleanup,
child summaries, actual diagnostics, exact 1.4.309 normative entries and curated
route files. The supplied normative report must match an independent recomputation.
Inputs and code are checked again after copying. Existing output is rejected.
Artifacts are built in a staging directory, byte-verified there, then atomically renamed to `handoff`. Any failure leaves a BLOCKED receipt and invalidates any staged success manifest; no successful handoff directory is published.
`--development` is explicit, visibly labelled and not final paired evidence.

## Output and strict whitelist

- `TRIAGE.zh.md` and `TRIAGE.en.md`: facts, exact diagnostics with log/line references,
  patch results, independent controls, oracle controls and remaining gates.
- Original C/GLSL/fix.patch files only from the fixed five-chain source allowlist.
- Actual per-case callback JSON/stdout/stderr/transfer logs, including the image
  heuristic-OFF non-PASS observation, only from fixed chain/case paths.
- Recomputed normative observation subset, original source/report hashes and
  paired commit IDs. Full validusage and vk.xml snapshots are not copied.
- Hash/byte-count/origin manifest and usage README.

No ELF binaries, compiler environment dump, arbitrary report fields, absolute
workspace paths, complete repository or runnable application is exported. Source
HTML remains inert JSON data; Markdown presents escaped identifiers and source
pages, not arbitrary external links. The handoff is a self-contained **reading
subset**, not a self-contained execution or full-provenance verification bundle.

## Independent offline byte verification

Preserve the manifest digest printed in the build receipt separately from the
package, then use the trusted repository verifier (never execute package content):

```sh
python checks19/build_diagnostic_handoff.py verify --package handoff \
  --expected-manifest-sha256 "$TRUSTED_MANIFEST_SHA256"
```

Missing/extra files, symlinks, path escapes, changed bytes or a changed manifest
are rejected. This is integrity against an independently trusted digest, **not a
signature**. An adversary who can rewrite both package and trusted digest can
replace the package. Verification does not rerun Vulkan or establish semantic truth.

## What the narrative does not upgrade

All scenarios are repository-authored fault injections, not external production
bugs. Descriptor lifetime is described as scenarios/recovery, never a fabricated
standalone patch. Negative exit 0 means an expected control completed, not API
success. Callback abort is identified. Unsubmitted zero arrays are placeholders,
not GPU output. Wrong-output controls test the oracle and are not new GPU defects.
Normative mapping is not a root-cause proof. CPU coherent evidence, heuristic
limits, CPU-only trace timings, missing noncoherent/mobile/device-loss tests and
open final gates remain explicit. No cross-chain resource or temporal causality
is invented. C3/C4/C7 progress is bounded presentation/traceability, not final DoD.
