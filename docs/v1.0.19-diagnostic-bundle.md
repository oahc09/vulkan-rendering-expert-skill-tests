# Bounded real diagnostic delivery stage

The original C3/C4 goal is executable evidence and repair, not an expanding list
of unrelated examples. `checks19/run_delivery_bundle.py` provides a single thin
entry point over existing implementations. It does not create a new runtime,
benchmark platform or replacement milestone plan.

## Required paths and scope

The bundle executes all five paths. There is no partial-success shortcut:

| Path | Positive oracle | Required negative/evidence boundary |
|---|---|---|
| Buffer transfer | 64 copied words | Missing dependency and altered access mask |
| Descriptor lifetime | Retired/rerecorded compute outputs | Pending update/reset, stale submission, wrong output |
| Pipeline interface | Actual compute readback | Type/binding mismatch and wrong output |
| Image compute | All 16 spatially varying pixels | Upload/readback dependencies, layout, wrong output, heuristic-off limitation |
| Validation + Perfetto | Actual callback plus two parsed CPU spans | Invalid size callback paired with clean creation; CPU spans are not GPU timing |

Each child preserves its own scope and run identity. The top-level ID only
identifies the delivery batch. It never joins unrelated Vulkan handles, resource
generations, frames or tool clocks. Tests validate expected-negative semantics
as well as successful process completion.

## Evidence contract

A new directory is reserved before launch. Source identities and exact two-repo
pair are checked; existing child reports cannot stand in for execution. Each
child's command, outcome, report and raw output are retained. Hashes bind the
recorded bytes and do not themselves authenticate the producer. The delivery
index is successful only after all required children satisfy their contracts.
Failure or timeout retains a non-success index and available partial evidence.
Tampered/missing output, unexpected identities or changed sources require review.

Example (paths and full commit IDs must refer to the actual authorized pair):

```sh
python checks19/run_delivery_bundle.py \
  --skill-root "$SKILL" --expected-skill-head "$SKILL_SHA" \
  --expected-tests-head "$TESTS_SHA" --tools "$SPIRV_BIN" \
  --include "$VULKAN_INCLUDE" --loader "$VULKAN_LOADER" \
  --trace-processor "$TRACE_PROCESSOR_BINARY" --output "$NEW_DIRECTORY"
```

Default mode requires the entry point itself in the declared committed HEAD.
`--development` explicitly marks a local uncommitted entry experiment and is
not final commit evidence. Existing output directories are rejected. A failed
run retains `delivery-index.json` with BLOCKED state and partial raw logs.

Use `--help` for exact arguments. Paths are explicit, using already available
authorized compiler/headers/loader/ICD/layers/SPIR-V tools and Trace Processor.
The entry never downloads or installs tools, changes environments or broadens
permissions. Do not run deliberate faults on production or unapproved devices.

## Relationship to final acceptance

This closes a bounded orchestration and reproducibility gap across the existing
real-tool paths. It is not a general scene parser, autonomous repair agent,
RenderDoc integration, physical-device matrix or Live model evaluation.
Authored examples retain their original provenance and are not promoted to real
external-engine bugs. Noncoherent device execution stays UNAVAILABLE_NOT_RUN.
All 36 original ALL19/E2E19 task statuses and four release seals remain separate;
no M0–M6 exit is implied by this local delivery gate.
