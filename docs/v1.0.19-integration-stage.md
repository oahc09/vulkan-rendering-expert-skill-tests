# Bounded delivery stage: image upload and compute consumption

This is a technical integration stage inside the existing candidate, not a new
M0–M6 milestone or a replacement development plan. M0 remains in progress and
all original ALL19/E2E19 tasks retain their current unverified state.

## Why this stage, not another API probe

Existing actual paths cover buffer transfer, ordinary descriptor lifetime and
compute buffer interfaces. They do not establish that image data moves through
upload, subresource layout transitions, image descriptors, compute access and
readback correctly. This stage targets that complete data path, relevant to
texture loading and compute postprocessing. Spatially varying input prevents a
shader that ignores the upload from accidentally satisfying a constant oracle.

## Exit contract

The implementation must retain, in one run identity:

1. Actual format/tiling/usage/type/extent/sample and memory compatibility queries.
2. A fixed authored failing baseline, compiled shader and source/binary hashes.
3. Upload, image state changes, descriptor bindings, compute and readback.
4. A real diagnostic for the missing dependency, with unsafe commands aborted.
5. An actually applied minimal repair that executes the entire data path with
   no unexpected diagnostics and every output pixel matching a CPU calculation.
6. An independent invalid-layout control and a wrong-output oracle control.
7. Subprocess result, capability failure, timeout, API error and cleanup handling
   that cannot silently become successful evidence.
8. Independent review, exact Skill/tests pairing, broad regression and CI.

The retained evidence file is `coverage/v1.0.19/image-compute.json`; its presence
alone is not acceptance. Tests bind its hashes to the executable sources and
verify the measured outcomes. Rerun instructions are beside the case sources.

## Original-plan contribution and boundaries

| Area | Contribution | Not closed |
|---|---|---|
| VK05 | Bounded image data movement and layout contract | All formats, compressed/multiplanar, arrays/mips/3D, sparse |
| VK06 | Transfer→compute→transfer→host dependencies | Multiple queues, memory-model completeness, all stage/access pairs |
| VK07–09 | Actual storage-image descriptors and compute consumption | All binding models, reflection, specialization and pipeline families |
| C3/C4 | Original fault, tool diagnostic, applied patch and output regression | External-engine causal repair and blind task delivery |
| C5/C6 | Correctness and fail-closed diagnostic execution | Performance/quality/thermal claims, physical/mobile reliability |
| C8 | Evidence-bound local regression | Model Live run, all-domain review and final release |

Host-coherent staging in the CPU ICD is not noncoherent validation. The previous
noncoherent capability gap remains `UNAVAILABLE_NOT_RUN`. No original task is
upgraded merely because this authored integrated example passes. Remaining
higher milestones require original-plan source/semantic closure, genuine
external-project or blind-task provenance and their respective execution scope.
