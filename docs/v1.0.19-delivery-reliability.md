# Bounded C6 tool-delivery reliability stage

The five-chain entry is executable, but final delivery also needs predictable
termination and trustworthy partial results. This stage addresses the process
workflow, not Vulkan device-loss, WSI or in-flight resource retirement semantics.

## Acceptance matrix

| Condition | Required outcome |
|---|---|
| Normal completion | All required children, output checks and source/artifact bindings still pass |
| Missing or failing tool | No overall PASS; preserve failure and available step logs |
| Per-step timeout | Stop the owned process group, retain timeout and cleanup outcome |
| Total budget exhausted | Stop launching further work; retain completed and interrupted evidence |
| Cancellation / interrupt | Non-success index, no later chain starts, preserve logs |
| Descendant ignores TERM | Bounded escalation confined to this invocation's group |
| Parent exits before descendant | Do not mistake direct-child exit for full group cleanup |
| Unrelated sentinel process | Remains alive; no process-name/global kill actions |
| Existing output directory | Reject without overwriting old data |
| Fresh retry after addressed failure | New run ID/directory; all required paths execute again |
| Interrupted index sent to resolver | Reject as a non-successful strict bundle |

The implementation must retain actual command, timestamps, timeout/cancellation
reason, result and termination actions. A best-effort cleanup must not be
reported as proven complete when descendants remain or ownership is uncertain.
Escaped process groups, if unsupported, are a declared boundary, not a reason
to kill arbitrary system processes.

## Evidence tiers

Process descendants and controlled timeout tests are CPU fixtures. They validate
supervision behavior, not GPU failure recovery. Actual five-chain success and
controlled cancellation/retry provide real workflow evidence; no driver hang,
production-process termination, system permission change or environment switch
is part of this stage. Device/scene generations and resource lifetimes keep
their separate original-plan acceptance rows.

## Recovery policy

Do not resume by editing an old PASS/BLOCKED index or mixing reports from runs.
Keep partial artifacts local, address the cause, and rerun into a new directory.
The existing exact-pair, source integrity, negative-control and output-oracle
checks remain mandatory. The successful result must still be accepted by the
version-paired normative resolver; cancelled/partial results must not be.

Implementation reference: [Python subprocess documentation](https://docs.python.org/3.12/library/subprocess.html).
A `Popen.communicate()` timeout does not itself terminate the child; this workflow
therefore owns explicit bounded termination and output collection. Process-group
and descendant behavior must be demonstrated separately by its fixture evidence.

The delivery entry accepts `--total-budget`, `--step-timeout`,
`--terminate-grace` (seconds) and optional `--cancel-file`. Budgets must be finite
and positive. Creating the supplied marker requests cancellation; SIGINT/SIGTERM
also request controlled stopping. The marker is never removed by the entry.
Pass a new marker path and output directory for recovery, retaining the cancelled
index and logs for inspection. Cleanup grace follows the runtime deadline;
it is not a guarantee of an instantaneous hard wall-clock cutoff.

This implementation is Linux process supervision with process-local subreaper
state restored after the step, not an OS-wide setting or service. Descendants
that deliberately escape the launched process group are outside the supported
contract; no global process scan or termination is used to chase them.
