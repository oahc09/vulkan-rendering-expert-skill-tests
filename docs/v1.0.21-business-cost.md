# v1.0.21 GPU-driven 成本留证

继续使用现有合理 CPU instancing、GPU fixed slots 和 GPU Count 路径。为每组业务场景先登记实际输入与构建身份，再对各路径采集正确性与成本。Engine Scale Lab 的同步读回结果可用于开发检查，业务实测格需要原始产品输入和业务模式采集。

## 输入与复验

```sh
python -X utf8 tools/delivery19.py business-cost /path/to/evidence/manifest.json
python -X utf8 -m pytest -q tests/test_business_cost21.py tests/test_delivery19.py
```

manifest 按 `{"path":"relative.json","sha256":"…"}` 引用同目录证据，具体字段实例见确定性 Host 用例。

| 文件 | 记录内容 |
|---|---|
| plan | 登记时间、最少时长与帧数、整帧 p95 上限及可选 p50/p99/实际呈现间隔门槛。每个 case 定义输入 hash、场景、种子、视图与分辨率、设备/driver、质量、测量方式、缓存、热状态和电源条件，固定两路实际构建与分别使用的渲染路径 |
| diagnostic | 此 plan、case、两路线构建与质量合同。可见集合、画面、容量与低能力模式分别记录结果，原始 Validation、读回和口径保留在采集证据 |
| 每次 business run | 此 plan、case、arm、路径、实际构建、完整采集帧数与全部整帧样本。记录独立运行 ID、实际时间窗、失败数、诊断读回启用状态、真实业务读回以及可取得的实际呈现间隔和各阶段成本 |

预先登记静态、稀疏更新、全量更新及至少一项多视图或容量边界。每个要得到限定范围结论的场景分别提供至少三次独立 A/B，执行时固定热状态、质量与输入，最好交叉安排 A/B 顺序。窗口时间和样本来自原始采集。报告检查提供的时间窗、哈希、作用范围及样本数，采集真实性由执行证据与独立评审确认。

报告输出每轮整帧和呈现间隔的样本数、p50、p95、p99，按最近秩计算。CPU 更新、录制、提交、上传字节、峰值常驻、GPU 关键区间和队列等待分项记录，缺项为 null。不同队列的重叠区间不相加。已确认画面或容量失败、候选运行失败或整帧 p95 更慢时保留 CPU 基线。少于三次合格对照或超出作用范围时要求重新测量。渲染路径未获得的低能力证据保留未知。

## 当前执行

使用固定 Host 输入验证三次独立记录、两次不足、较慢回退、运行失败、诊断读回混入、帧数不符及同设备重叠窗口。新增七项与原交付合同合计 40 项通过。业务收集器处理已有归档，运行入口不启动产品或设备。

当前没有可绑定到真实产品的三次持续 A/B，V21-05 的业务成本、实际呈现、移动功耗与 P2 适用区间仍未验证。V21-04 的 llvmpipe 离屏诊断只计入对应正确性证据。
