The current checker validates the Skill commit, tree, version, candidate status,
source cleanliness, inherited plan/registry hashes and Tests base ancestry.
The regression suite separately locks the exact 200 allowed package paths
and their content hashes via the canonical sorted manifest digest, and verifies
reproducible ZIP creation and CRCs. This is not a registry upload or approval.
The actual Tests checkout SHA is printed at execution. Omitting `--pair`
preserves the earlier v1.0.19 immutable pairing; historical CORE17/TEXT18
cohorts and the separate Scene B fixture remain unchanged. No hosted workflow
replaces or changes the historical lane. The separate `current20-candidate.yml`
workflow runs the current pair, records raw logs, unfiltered JUnit, exact pair
SHA/tree and package hashes, and uploads available artifacts even after failure.
Locally, use the same receipt runner:

```sh
python checks19/run_current_receipt.py --skill /path/to/exact-skill \
  --tests-sha "$(git rev-parse HEAD)" --out /tmp/new-current20-evidence
```

The output path must not already exist and must be outside both checkouts.
The receipt lane deliberately does not execute a Live model or attest to GPU
performance; skips and historical deselections remain visible. For a
reproducible rerun, check out the exact Tests SHA printed in the receipt before
calling either command. The pair manifest freezes the reviewed ancestor, not a
self-referential Tests commit SHA.

This is a regression lane, not acceptance of the original 24 ALL19 paired
model task groups or 12 E2E19 engineering tasks. Those entries are still
UNVERIFIED. A green run is not a publication approval or proof of live models,
mobile/physical GPU behavior, performance, or every supported driver.
