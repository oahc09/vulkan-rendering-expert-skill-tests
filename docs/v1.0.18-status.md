## CPU lifecycle hardening

The CPU reference now rejects reuse of completed upload values, consumer-domain
aliasing with the upload timeline, and regressing/reused consumer signal values.
Cancellation blocks new publication/acquisition without discarding upload or
already-retained consumer retirement obligations. Validation failure does not
partially mutate slot state. These calls require external serialization and
trusted per-device completion observations; they do not implement locking or
prove GPU progress. Balanced retain/release remains an owner contract, not an
independently validated snapshot-token system.

Upload and consumer timeline values use uint64 without narrowing; generation
and glyph IDs retain their separate bounds. Values beyond uint64 and booleans
are rejected before mutation.
