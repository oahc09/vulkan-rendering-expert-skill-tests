# Fixed reference font preload repair

`checks19/repair_reference_fonts19.py` creates a fresh isolated copy of the registered P4 all-Vulkan 1.4.368 source/generated tree. It applies only the previously tested KaTeX preload path substitution, removes the copied reference HTML directory, and invokes the official `manhtmlpages -j4` target for all 3553 entities and 477 aliases. The original Docs, P4 and P5 outputs are never edited.

Required arguments are `--source-root` (registered P4 baseline), `--baseline-build` (registered P5 receipt and HTML), `--runtime-root` (registered private Debian runtime), and fresh `--output`. Optional `--cancel-file` uses the existing owned-process supervisor and a 1800-second execution budget. No caller commands or patch paths are accepted.

Every resulting entity must equal its original P5 bytes with exactly nine `../katex/fonts/` hrefs changed to `../../katex/fonts/`. Each of the nine distinct assets must exist as a regular WOFF2 file within the output root. Original and modified Ruby source bytes, all executing repository helper/entry source snapshots, command streams, runtime identities and per-page HTML hashes are retained. The snapshot is execution evidence, not authenticated authorship.

The full offline href audit runs again without changing its defect rules. Navigation and fragment findings remain findings, external URLs are not fetched, and image/script/CSS references are outside that audit. Successful font repair is not all-links success or browser font/visual validation. The unchanged full specification is retained, not rerendered by this entry; its path behavior was tested separately in the prior narrow probe.

The source configuration includes 482 extensions (including five provisional) and 20 core attributes. This is documentation selection, not platform execution, normative semantic review or upstream acceptance of the patch. Existing 66 empty sections retain their prior scope; this operation does not repair them.

## Preserved first-validator failure and offline recheck

The first full render completed successfully, but its original validator counted an additional external FontAwesome preload as a tenth KaTeX preload and rejected the output. That `BLOCKED` report and its actual implementation snapshots are preserved. The corrected selector counts only KaTeX preloads; byte equality still requires every other byte, including the external FontAwesome URL, to remain unchanged.

`checks19/verify_reference_font_repair19.py` accepts that specific saved false-rejection with all five successful steps, an externally supplied `--expected-report-sha`, and the same baseline/source/runtime roots. It does not rerender or upgrade the old receipt. It writes a separate fresh output binding the original execution, saved implementation, raw logs, actual generated bytes, current validator snapshots, all 3553 comparisons and the full href audit. Use `--build-root` for the failed render output and `--output` for the new receipt directory. Tests using actual outputs require `VULKAN_REFERENCE_FONT_REPAIR19_BUILD` and `VULKAN_REFERENCE_FONT_REPAIR19_BASELINE`; missing assets are explicitly skipped, not represented as passed real execution.

The original failed build receipt contains the five commands, exits and cleanup results but no execution-time stream digests. The offline report hashes the saved streams at recheck time, not retroactively at execution time. Its explicit boundary is retained; an independent review witness separately records the saved streams. The offline checker also compares all five argv lists against this fixed configuration and target, not merely their labels.

## Recorded fixed-cohort result

The initial official render took 296.35 seconds for all 3553 pages and 477 aliases;
its preserved first-validator failure is not relabeled. The corrected offline
verification and separate independent byte review confirm exactly 31,977 preload
href replacements and nine real WOFF2 files. No other HTML bytes change.

The complete static href audit retains 224,102 occurrences: 193,150 local resolved,
2 missing local targets, 16,280 missing fragments and 14,670 external/mailto links
not fetched. Only the 31,977 font-path findings moved from missing to resolved.
The compact evidence record is `coverage/v1.0.19/reference-font-repair.json`;
raw original build, source snapshots, per-page hashes and full occurrence output
are separately retained and reproducible with the fixed inputs. The source-backed
fragment diagnosis is in `reference-dynamic-fragments19.md`; it is not a repair.
