## Bounded stages and stop conditions

1. **R: fixed dual-XML structural closure.** Retain every element, attribute,
   text/tail and ancestry coordinate, including unknown tags. Preserve API,
   platform/protect, supported/provisional, require/remove, alias, structextends
   and raw dependency expressions. Rebuild from fixed bytes and reject omitted
   members/conditions/edges. Relations may be unresolved or ambiguous. A syntactic
   alias target is not semantic substitutability, feature enablement or legality.
   Stop once both exact inputs reproduce deterministically and independent
   mutation controls reject an incomplete or altered inventory.
2. **P: complete normative source closure.** Enumerate every tracked source at the
   frozen Git tree, categorize purpose and explicit exclusions, record include
   and generation dependencies, then evaluate separately fixed Vulkan/SC/platform
   configurations. Preserve unresolved generated includes. Do not declare P
   complete from XML R or a recursive `.adoc` file list.
3. **H: external definitions and generated references.** Freeze separate Headers,
   SPIR-V and tool cohorts; reconcile symbols/conditions/versions with R/P and
   explicitly list missing or nonmatching items. Version bridges require review.
4. **S: actual semantic review.** For each bounded family register purpose,
   non-purpose, query/enable conditions, object lifecycle, calling order,
   concurrency, failure/recovery, tool limits and fallback. Bind exact normative
   spans, card sections, executable positive/negative controls and evidence.
   Independently resolve contradictions, not merely missing strings. Existing
   HOST contract evidence can be reused only under exact content and scope pins.
5. **A: original acceptance.** Evaluate original ALL19/E2E19 and other seals under
   their own pre-registered denominators. R/P/H/S are prerequisites, not a waiver.

## State discipline

Keep SOURCE_FROZEN, STRUCTURE_INDEXED, ROUTED, REVIEWED_L1, REVIEWED_L2 and
EXECUTED_WITHIN_SCOPE as separate fields. Structural inventory begins entirely
UNREVIEWED. A review declaration is not authenticated independent acceptance.
A passing subset must not upgrade its whole extension, domain or corpus.

Structural counts describe source nodes, not unique APIs or knowledge units.
Registration and semantic percentages remain UNKNOWN until their full applicable
frozen denominator and acceptance rule are established. The existing 497 scopes,
309 VUID cohort and 23 HOST entry registry are useful partial coordinates, not
an alternative denominator that makes final completion easier.

## P1 execution boundary: source graph and a scoped semantic bridge

The first P increment freezes the entire tracked Docs tree, including executable
scripts and configuration, not only `.adoc` text. Literal includes, attribute
macros, conditions and generation inputs remain distinct. A lexical graph does
not evaluate AsciiDoc or select Vulkan/SC/platform configurations. Single-line
conditional bodies are not open blocks; self-file tagged includes are not by
themselves invalid cycles. Unresolved generated or attributed includes remain
explicit blockers. Successful future compilation is insufficient: the fixed
source's quiet-include-failure extension is loaded by ADOCVUEXTS for validusage and can suppress missing-include failures there; it is not the default HTML path.

The dedicated-allocation preference/requirement bridge reuses a bounded existing
HOST contract. Bind the actual normative paragraph, enclosing source conditions,
fixed source bytes, helper/test bytes and observed positive/negative controls.
Preference permits suballocation; a requirement does not. The raw paragraph is
not an enabled feature proof, not equivalent to the separately pinned309 VUID
corpus, and not hardware verification. No broader memory-family L1/L2 completion
is awarded. Stop P1 after deterministic full source reconstruction, exact scoped
mapping and independent loss/condition/fake-closure controls. P remains BLOCKED
until configurations, expansion/generated outputs and their completeness checks
are actually established.

## P2 execution boundary: official generated includes, fixed configuration

Execute the pinned official generator recipes only in a fresh exported source
copy and separate output. Explicitly select Vulkan (not Vulkan Base/SC), core
1.0 through1.4 and an empty extension selection. Record actual Make/Python tools,
argv, exits, logs and generated bytes. Preserve source licenses and do not modify
the shared CTS/Vulkan-Docs checkout. A generated filename alone is insufficient:
compare a second clean generation and independently inspect required symbols and
include-target presence. Timestamps/marker files must not be confused with
normative content equivalence.

This configuration is a bounded standard-core cohort, not every extension,
platform or SC. If Ruby/Asciidoctor is unavailable, record that limitation and do
not invent rendered or preprocessed outputs. An include whose target exists is
not necessarily active or semantically expanded: condition selection, attributes,
tag/line options, recursive composition and generated Reference pages retain
separate unresolved states. Report missing targets without assuming all are
active requirements. A quiet generator/build exit does not settle this question.

## P3 execution boundary: actual preprocessor observations

Install any missing runtime only from authenticated official packages into an
independent current-workspace root; retain package/index provenance and hashes.
Do not change system configuration, trust settings or the original Docs checkout.
Fix Ruby, Asciidoctor, syntax-highlighter and other actually loaded dependencies.
Use the same explicit core1.4 source/configuration as P2, not a moving upstream.

Observe actual preprocessing without replacing its semantics. Preserve original
reader behavior and compare observed/unobserved results. Record active include
sources, selected content and conditional/tag handling; inactive branches must not
be mislabeled missing dependencies. Delete an active include and alter selected
tag content for negative controls; an inactive deletion alone must not manufacture
an active failure. Verify output/evidence, not only a zero exit or a log label.

The Asciidoctor stage and full official HTML target remain distinguishable: the
latter also invokes Node/KaTeX math processing. Reference extraction/rendering,
all extension/platform/SC configurations, cross-reference completeness and full
semantic acceptance have independent gates. A core cohort's success must not
close these. Never use validusage's quiet missing-include extension to make a
missing active input appear accepted.

## P4 execution boundary: registered all-Vulkan VU and Reference outputs

Run the fixed official `makeSpec -spec all -version 1.4` from fresh exports,
including its own generated includes, HTML, xrefMap, Antora pageMap and VU
extraction. Do not combine the P3 core inventory with this configuration. The
actual attribute inventory, including provisional and platform-specific records,
is part of its identity; all-Vulkan documentation is not Vulkan SC or platform
runtime acceptance. Keep the older309 VUID cohort unchanged.

Reference source extraction and HTML rendering have distinct denominators.
A complete generated source inventory plus two rendered representative pages
cannot establish that every Reference page renders. Report the exact rendered
page list; alias link closure and unrendered pages remain separate work.

Official `quiet-include-failure` deliberately suppresses absent inputs in the VU
path. Page mapping can warn and still exit successfully. The frozen schema uses
Draft4 with a newer `const` keyword, which Draft4 ignores; missing Ruby schema
validation also only warns. Preserve these source behaviors. Independently apply
the declared schema and a separately labeled strict fixed-cohort contract; do not
silently upgrade the schema or rewrite original output to obtain a pass.

Require bidirectional VUID/HTML-anchor reconciliation, exact literal page-map
associations, actual observation and complete output provenance. Exercise missing
active include and missing map entries through the actual official tools, then
require the outer audit to reject their apparently successful output. Exact
fixed-cohort agreement is not a general condition solver or L1/L2 semantic proof.
