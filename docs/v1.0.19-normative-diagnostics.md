# Version-paired normative diagnostic stage

## Goal and acceptance

Connect the existing strict real-tool delivery bundle to versioned normative
requirements and on-demand Skill routes. This is a reusable interpretation entry,
not a new fault example or an autonomous diagnosis service.

The stage must:

1. Verify the exact strict bundle, retained source/tool/report/artifact identities
   and raw logs. A previous PASS string by itself is not evidence.
2. Extract observations from the raw callback/log bytes, with chain/case/phase
   and provenance retained. Cross-check the child reports instead of accepting
   a hand-authored summary as a new observation.
3. Index the complete pinned valid-usage source under its schema, API version,
   source revision and SHA256. Retain command/structure ownership, condition keys,
   normative text and page. Reject malformed or conflicting duplicates.
4. Resolve exact VUIDs only when the observed Validation version matches the
   normative source cohort. Preserve distinct conditional entries. Unknown VUIDs
   or incompatible versions require review, not a fabricated successful match.
5. Separate SyncVal hazards from normative VUIDs and preserve actual diagnostic
   mode/heuristic boundaries. Do not invent a spec entry for a tool identifier.
6. Attach explicit, existing, version-bound knowledge routes as navigation only.
   The route is neither proof of causation nor a declaration of domain completion.
7. Exercise independent unknown-ID, wrong-version, evidence-corruption and
   source-conflict controls; run the real stage on a fresh strict delivery bundle.

## Source cohorts remain separate

The installed official Vulkan headers/Validation cohort is 1.4.309. Its
`validusage.json` has schema2, source commit
`43d153dd7f9f5e8b9f79d26d868c82a82b9ef80b`, and SHA256
`f61afea8ca6097342cae1b65bfab81675ee7fdc2d809403e083329b7d56597a7`.
The existing broad `vk.xml` inventory is 1.4.368. Counts, source revisions and
semantic claims from these cohorts must not be combined into a fictitious
single frozen specification denominator. The local valid-usage file is an input;
this stage does not silently fetch a moving latest source.

## Boundaries

Indexing requirements is source coverage, not all-domain L1/L2 semantic review.
Matching a diagnostic is not automatic proof of defect, root cause, applicability
of every conditional rule, repair success or feature support. Source HTML/text
is untrusted data: no script execution, automated navigation or local path access
from its content. A lookup result does not authorize code changes or publishing
user data. Original ALL19/E2E19, external engineering, Live, hardware and release
seals retain separate status. Noncoherent execution remains unverified.
